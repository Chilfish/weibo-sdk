## 归档 / 单条微博请求并发化

**触发**：`streamArchive` 当前严格串行：一页内逐条执行 `onRaw` → 评论翻页 → `yield` → 转发翻页。时间线一页 20 条、每条评论/转发都要多次往返时，延迟被放大成 `20 × 子请求数`。用户提出至少页内应能并发；`tweets.context()` 里的长文 / 作者 / 评论也是互不依赖的请求，同样应并发。

**判断**：

- **分页仍串行**：`mymblog` / `searchProfile` / `max_id` / `since_id` 游标都依赖上一页响应，跳页并发会破坏 checkpoint 与去重语义，不做。
- **并发窗口按「条目」计算**：同一页内预取后续条目的独立子请求（评论链、转发首页），产出顺序、`onRaw` 顺序、`checkpoint.lastTimelineMblogId` 的「最后一条完整处理项」语义全部保持不变。
- **不做乱序 yield**：下游按顺序落盘、checkpoint 取连续已完成前缀；乱序会让续跑漏项。
- **默认窗口 3**：与 `config.maxConcurrent`（令牌桶容量）对齐；默认值保持有界，`concurrency: 1` 可回到完全串行。实际 HTTP 并发仍由 `RateLimitService` 令牌桶与 432 全局暂停兜底。
- **单条微博内部并发**：`context()` 在 `statuses/show` 之后并行拉长文、作者、评论；`enrich()` 的 `show` 与 `longtext` 互不依赖，也并行。评论自身分页仍是串行游标。
- **提前退出安全**：预取任务在 `finally` 里 `Promise.allSettled` 收敛，并对未 awaited 的 promise 挂空 `catch`，避免浮动 Promise / unhandled rejection（skill.md 第七条）。

**改动**：

- `ArchiveStreamOptions.concurrency`（默认 3，范围 1–8）+ `streamArchive` 页内滑动预取窗口；`streamReposts` 接收已预取的转发首页，并在转发页内按同一窗口预取评论。
- `tweets.context()`：`show` 后并行 `longtext` / 作者资料 / 评论抽样，结果仍按原逻辑组装。
- `tweets.enrich()`：`show` 与 `longtext`（`includeLongText` 时）并行。
- CLI `archive --concurrency <n>`。
- 新增并发回归测试（请求在首个结果返回前已启动、产出顺序不变）。

**提交计划**：

1. `feat(archive): prefetch per-item requests within a page`
2. `perf(tweets): parallelize independent enrichment requests`
3. `docs: record archive request concurrency design`

## 调研：插件化架构、传输适配与凭证池

**触发**：评估「多账号 token 池是否能提升 token 无关端点的吞吐」，同时希望把自定义 fetch（Worker / Edge / 不用 axios）、日志、遥测、hooks 收敛成可组合的插件体系；下游还要求 SDK 开箱即用，并保证 npm 包被再次打包后的产物准确。

**方式**：

- 阅读 `FetcherService` / `AuthProvider` / `GuestTokenService` / `RateLimitService` / `RetryPolicy` / `capabilities` / `package.json` / `tsdown.config.ts` / 导出测试。
- 用 `gh api` 直接读 Octokit、before-after-hook、Ky、unjs/hookable、Vite 的插件与钩子源码，对照其顺序、短路、错误与注入方式。

**结论**：

1. **不做多账号 token 池**。`auth: 'guest'` 端点是身份无关，换 token 不改变数据；432 主要打在 IP / 行为维度，池化收益低且额外发 token 请求。账号级端点轮换会改变数据，非账号级 cookie 端点也会受可见范围影响。保留 `CredentialResolver` 接缝与 `credential_id` 观测即可。
2. **插件化采用三层结构**：Ports（`WeiboTransport` / `CredentialResolver` / `Clock` / sinks）→ Core 状态机（retry / rate-limit / auth-refresh / okPolicy / Zod）→ Plugins（生命周期钩子 + transport 中间件 + 只读 observer）。核心状态机不插件化，无插件时走 identity 快路径。
3. **自定义 fetch 是最有价值的入口**。抽 `WeiboTransport` 后，Worker / Edge / 测试替身 / 浏览器去 axios 一起解决，`GuestTokenService` 的 `GuestFetch` 合并到同一注入点。
4. **下游产物需要独立门禁**。当前 `exports` 缺少 `types` 条件、`sideEffects: false` 与 CLI 顶层 `runMain()` 不一致、没有 `engines`、browser 内联 axios/zod、导出测试只看字段形状。需要 `publint` + `attw` + `pnpm pack` 真实安装 + Vite/esbuild + tree-shaking + Worker smoke。

**文档产出**：

- 新增 [research-plugin-architecture-2026-10-21.md](../planning/research-plugin-architecture-2026-10-21.md)（现状盘点、token 池结论、外部调研、目标架构、DX 契约、PF1–PF7 行动计划、测试与风险）。
- 新增 [package-integrity.md](../engineering/package-integrity.md)（当前发布形态、下游消费矩阵、R1–R12 风险、目标 `exports` / `sideEffects` / `engines`、tarball 核验矩阵、CI 门禁、编码规则）。
- 新增 ADR-014（三层扩展）、ADR-015（不做 token 池）、ADR-016（下游产物契约）。
- `backlog.md` 新增 PF1–PF7，并把「多账号 token 池轮换」移入已移除；`docs/README.md` / `technical-spec.md` / `release-checklist.md` 同步索引与规划标注。

**提交计划**：

## CLI 公共输出格式：`--format`（试点 `user info`）

**触发**：除 `tweet context` 外，CLI 命令都直接打印 `JSON.stringify(data, null, 2)`。用户资料、微博这类嵌套 JSON 对人阅读成本高，Agent 也需要把大段原始结构再翻译一遍。希望有一个公共 `--format`，可选 `json` / `markdown` 等视图。

**判断**：

- **默认仍是 JSON**：脚本、`jq` 和 NDJSON 流是既有契约，默认值不变；`--format` 是显式选择的视图，而不是替换默认。
- **参数与分发共用**：`src/cli/output.ts` 提供 `outputFormatArg`（`--format` / `-f`）、`parseOutputFormat`（未知值抛 `CONFIG_INVALID`）和 `renderOutput`（`json` 走 `JSON.stringify`，其余交给调用方传入的渲染器）。新命令只需展开参数 + 一个渲染函数。
- **渲染器放 `src/models/view/`**：与 `renderTweetContextMarkdown` 一致，`render*Markdown` 是纯函数，不发请求、不写 stdout，便于单测。
- **先试点 `user info`**：它的数据形状与微博上下文不同，能验证「公共参数 + 每命令渲染器」不是只为 tweet 写死；`whoami` 输出同一个 `User` 模型，后续可直接复用 `renderUserMarkdown`。
- **流式命令不接入**：`*-stream` / `archive` / `media download` 的 NDJSON 是逐行协议，混入 Markdown 会破坏管道消费。
- **不伪造缺失字段**：简介、生日、公司等未公开时整行省略；真实 `sunshine_credit.level` 是「阳光信用较好」这类文案，渲染时去掉重复的「阳光信用」前缀。

**提交计划**：

1. `feat(cli): add shared --format option with markdown output`
2. `docs: document cli output formats`

**改动**：

- 新增 `src/cli/output.ts`：`outputFormatArg`（`--format` / `-f`）、`parseOutputFormat`、`renderOutput`。
- 新增 `src/models/view/User.ts`：`renderUserMarkdown`，纯函数，未公开字段整行省略。
- `user info` 接入 `--format`；先校验格式再发请求，非法值不会先打一次网络。
- 文档同步：`cli.md` / `README.md` / `AGENTS.md` / skill（`SKILL.md` + `references/cli.md`）/ `playground/cli/README.md` / `tests/TEST_INDEX.md`。

**验证**：

- `pnpm run typecheck`、`pnpm exec eslint <changed files>` 通过。
- `pnpm vitest run`：**782 passed / 23 skipped**（新增 10 条用例）。
- 真实访客请求 `user info 1111681197 --guest --format markdown` 输出用户卡片；不带 `--format` 仍为原来的 JSON。
- `--format yaml` 在发请求前返回 `CONFIG_INVALID`（`context.field = 'format'`），退出码 1。

**后续**：按命令逐个接入——`whoami` 可直接复用 `renderUserMarkdown`；`tweet detail` 可复用 `buildTweetContext` + `renderTweetContextMarkdown`（不额外发请求）。

## 契约 v2：移除 `textHtml` 与归档 `longText`

**触发**：观察归档 JSON 时发现 `tweet.textHtml` 与 `ArchivedTweet.longText` / `quotedLongText` 重复。排查确认：

- `normalizeTweet` 从未把 longtext 结果写进 `text`；归档里的 `longText` 是 `scripts/archive-user.ts` 额外请求 `/ajax/statuses/longtext` 后单独存放的字段。
- `statuses/show` 请求带 `isGetLongText=true`，上游已经返回全文。真实请求 `RmX9TuHhV` 验证：`tweet.text` 1108 字符，`/statuses/longtext` 的 `longTextContent_raw` 也是 1108 字符，内容一致。
- `textHtml` 是上游 HTML（表情 `<img>`、链接卡片锚点、`<br>`），语义信息已由 `topics` / `linkCards` / `atUsers` / `media` 覆盖；SDK 内部不消费该字段。

**决定**：按契约规则升级到 v2，一次性删除，不保留兼容别名。

- `ITweet` / `ITweetComment` 移除 `textHtml`；`TWEET_CONTRACT_VERSION` 升为 `2`。
- `ArchivedTweet` 移除 `longText` / `quotedLongText`；归档脚本不再额外请求 `/statuses/longtext`。
- 归档格式升级为 `weibo-user-archive/v2`；`schemas/weibo-user-archive/v1.json` 作为历史文件保留，新文件使用 `v2.json`。
- 新增 `migrateTweetV1toV2(record)` 纯函数：递归删除 `textHtml`，供下游读取 v1 记录时迁移。
- `tweets.enrich({ includeLongText: true })` 保留为显式补拉入口，不改变“show 默认已含全文”的事实。

**验证**：

- `pnpm run typecheck`、`pnpm test --run`（**783 passed / 23 skipped**）、`pnpm run build` 全部通过。
- 真实请求 `tweet detail RmX9TuHhV`：`text` 1108 字符，输出已无 `textHtml`。
- 真实归档 `7679065628 --since 2026-10-16 --until 2026-10-16`：输出 `weibo-user-archive/v2`，记录无 `longText` / `quotedLongText` / `textHtml`。
- 提交：`dffce6d feat(contract)!: remove textHtml and archive longText`（代码 / 测试 / 文档同一提交；工作区里并行的 `--format` 改动未纳入）。

## 推广 CLI `--format`（全量查询命令）

**触发**：试点 `user info` 后，把 `--format` 推到所有「一页 / 一次请求」的查询命令，避免人和 Agent 每次都要自己翻译 raw JSON。

**实现**：

- `src/cli/output.ts` 增加 `createPrinter(args)`：命令开头解析一次格式（非法值在发请求前失败），之后只传渲染器。
- 新增渲染器（`src/models/view/`，全部纯函数）：
  - `TweetList.ts`：微博列表 / 评论 / 点赞者 / 评论通知 / 点赞通知。转发微博当前作者没有正文时回退原微博，并显式标注 `转发 @原作者：`，不把原文当成转发者的观点。
  - `UserList.ts`：关注 / 粉丝 / 我的关注（特别关注与普通关注按 uid 去重）。
  - `Collections.ts`：关注分组 / 微博分组 / 超话分类 / 超话列表 / 相册 / 热搜。
  - `TweetCard.ts`：单条微博复用 `buildTweetContext` + `renderTweetContextMarkdown`（不额外发请求）。
  - `Session.ts`：`whoami --guest` 的 token 元信息（不含 token 明文）。
  - `format.ts`：计数 / 时间 / 摘要 / 分页说明的公共工具；`User.ts` 的 `formatCount` 改为复用。
- 接入：`user` 5 个、`tweet` 9 个、`follow` 3 个、`favorite list`、`like list`、`comment mine`、`notification` 2 个、`media albums`、`topic` 2 个、`trends`、`whoami`。
- raw 响应命令通过现有归一化函数转成领域模型再渲染（`normalizeComment` / `normalizeTweet` / `new Tweet`），不新增对 raw 字段的猜测。
- 未接入：流式命令 / `media download` / `archive`（NDJSON 是逐行协议）、`favorite tags`（标签元素结构尚未抓包）、公开搜索（上游不可用）、`capabilities` / `schema diff`（诊断输出）。
- `CHANGELOG.md` 的 `Unreleased` 增加 `新增` 条目。

**验证**：

- `pnpm run typecheck` / `pnpm exec eslint` 通过；`pnpm vitest run`：**807 passed / 23 skipped**（本轮新增 25 条用例）。
- 真实访客请求抽查：`whoami --guest`、`trends`、`user timeline`、`tweet detail`、`tweet comments`、`follow fans`、`media albums`、`topic list` 的 `--format markdown` 均输出可读视图；默认 JSON 未变。
