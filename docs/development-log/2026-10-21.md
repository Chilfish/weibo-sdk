## 归档 / 单条微博请求并发化

**触发**：`streamArchive` 当前严格串行：一页内逐条执行 `onRaw` → 评论翻页 → `yield` → 转发翻页。时间线一页 20 条、每条评论/转发都要多次往返时，延迟被放大成 `20 × 子请求数`。用户提出至少页内应能并发；`tweets.context()` 里的长文 / 作者 / 评论也是互不依赖的请求，同样应并发。

**判断**：

- **分页仍串行**：`mymblog` / `searchProfile` / `max_id` / `since_id` 游标都依赖上一页响应，跳页并发会破坏 checkpoint 与去重语义，不做。
- **并发窗口按「条目」计算**：同一页内预取后续条目的独立子请求（评论链、转发首页），产出顺序、`onRaw` 顺序、`checkpoint.lastTimelineMblogId` 的「最后一条完整处理项」语义全部保持不变。
- **不做乱序 yield**：下游按顺序落盘、checkpoint 取连续已完成前缀；乱序会让续跑漏项。
- **默认窗口 3**：与 `config.maxConcurrent`（令牌桶容量）对齐；默认值保持有界，`concurrency: 1` 可回到完全串行。实际 HTTP 并发仍由 `RateLimitService` 令牌桶与 432 全局暂停兜底。
- **单条微博内部并发**：`context()` 在 `statuses/show` 之后并行拉长文、作者、评论；`enrich()` 的 `show` 与 `longtext` 互不依赖，也并行。评论自身分页仍是串行游标。
- **提前退出安全**：预取任务在 `finally` 里 `Promise.allSettled` 收敛，并对未 awaited 的 promise 挂空 `catch`，避免浮动 Promise / unhandled rejection（skill.md 第七条）。

**改动**：

- `ArchiveStreamOptions.concurrency`（默认 3，范围 1–8）+ `streamArchive` 页内滑动预取窗口；`streamReposts` 接收已预取的转发首页，并在转发页内按同一窗口预取评论。
- `tweets.context()`：`show` 后并行 `longtext` / 作者资料 / 评论抽样，结果仍按原逻辑组装。
- `tweets.enrich()`：`show` 与 `longtext`（`includeLongText` 时）并行。
- CLI `archive --concurrency <n>`。
- 新增并发回归测试（请求在首个结果返回前已启动、产出顺序不变）。

**提交计划**：

1. `feat(archive): prefetch per-item requests within a page`
2. `perf(tweets): parallelize independent enrichment requests`
3. `docs: record archive request concurrency design`

## 调研：插件化架构、传输适配与凭证池

**触发**：评估「多账号 token 池是否能提升 token 无关端点的吞吐」，同时希望把自定义 fetch（Worker / Edge / 不用 axios）、日志、遥测、hooks 收敛成可组合的插件体系；下游还要求 SDK 开箱即用，并保证 npm 包被再次打包后的产物准确。

**方式**：

- 阅读 `FetcherService` / `AuthProvider` / `GuestTokenService` / `RateLimitService` / `RetryPolicy` / `capabilities` / `package.json` / `tsdown.config.ts` / 导出测试。
- 用 `gh api` 直接读 Octokit、before-after-hook、Ky、unjs/hookable、Vite 的插件与钩子源码，对照其顺序、短路、错误与注入方式。

**结论**：

1. **不做多账号 token 池**。`auth: 'guest'` 端点是身份无关，换 token 不改变数据；432 主要打在 IP / 行为维度，池化收益低且额外发 token 请求。账号级端点轮换会改变数据，非账号级 cookie 端点也会受可见范围影响。保留 `CredentialResolver` 接缝与 `credential_id` 观测即可。
2. **插件化采用三层结构**：Ports（`WeiboTransport` / `CredentialResolver` / `Clock` / sinks）→ Core 状态机（retry / rate-limit / auth-refresh / okPolicy / Zod）→ Plugins（生命周期钩子 + transport 中间件 + 只读 observer）。核心状态机不插件化，无插件时走 identity 快路径。
3. **自定义 fetch 是最有价值的入口**。抽 `WeiboTransport` 后，Worker / Edge / 测试替身 / 浏览器去 axios 一起解决，`GuestTokenService` 的 `GuestFetch` 合并到同一注入点。
4. **下游产物需要独立门禁**。当前 `exports` 缺少 `types` 条件、`sideEffects: false` 与 CLI 顶层 `runMain()` 不一致、没有 `engines`、browser 内联 axios/zod、导出测试只看字段形状。需要 `publint` + `attw` + `pnpm pack` 真实安装 + Vite/esbuild + tree-shaking + Worker smoke。

**文档产出**：

- 新增 [research-plugin-architecture-2026-10-21.md](../planning/research-plugin-architecture-2026-10-21.md)（现状盘点、token 池结论、外部调研、目标架构、DX 契约、PF1–PF7 行动计划、测试与风险）。
- 新增 [package-integrity.md](../engineering/package-integrity.md)（当前发布形态、下游消费矩阵、R1–R12 风险、目标 `exports` / `sideEffects` / `engines`、tarball 核验矩阵、CI 门禁、编码规则）。
- 新增 ADR-014（三层扩展）、ADR-015（不做 token 池）、ADR-016（下游产物契约）。
- `backlog.md` 新增 PF1–PF7，并把「多账号 token 池轮换」移入已移除；`docs/README.md` / `technical-spec.md` / `release-checklist.md` 同步索引与规划标注。

**提交计划**：

1. `docs: plan plugin architecture, transport port and package integrity`
2. `docs(adr): record extension layering and package contract`

**边界**：本轮只写文档，未改代码；`new WeiboSDK({})` 的运行时行为不变。下一步从 PF1（Transport 端口）开始，默认仍用 `AxiosTransport`，确保零行为变化。

- **PF3**：`AuthProvider.ts` 提升为 `CredentialResolver.ts`（`Credential` / `CredentialResolver` / `SingleCredentialResolver`）；Cookie 凭证 id 使用 FNV-1a 指纹（`cookie-xxxxxxxx`），guest 为 `guest-primary`。telemetry / 错误 context 增加 `credential_id`。`likes.list` 经确认按目标 uid 读取，**不标记** `accountScoped`。
- **PF4**：新增 `src/services/internal/plugins/`（`types` / `pipeline` / `index`）。`plugins` 在构造期编译，`pre → normal → post` 排序；重名 / `apiVersion !== 1` 抛 `CONFIG_INVALID`。transport 中间件用 `reduceRight`，`pre` 位于最外层，与 hooks 顺序一致。`beforeRequest` / `afterResponse` / `beforeRetry` / `onError` / `observe` 已接入；`beforeRetry` 使用最近一次真实请求上下文（含鉴权头）；`onError` 可替换错误后再交给 legacy hooks。`logging` 死配置删除。
- **PF5**：`exports` 改为 `types` 优先条件对象；`engines.node >= 20.16`；CLI 拆分为 `src/cli.ts`（命令树）/ `src/cli-bin.ts`（`runMain`），`bin` 指向 `dist/cli-bin.mjs`，`sideEffects: false` 成立。新增 `lint:package` / `verify:package` / `test:bundle` 三个脚本。
- **PF6（文档部分）**：新增 [plugins.md](../engineering/plugins.md)；README / AGENTS / technical-spec 增加 transport / plugins 用法与默认值。playground / SKILL 示例留待后续补充。

## 打包：CLI-only 依赖内联（R11）

**触发**：确认 ESM-only + d.ts 分发保持不变，核心 SDK 与 CLI 的产物继续分离；希望 SDK-only 安装与 `pnpm dlx` 少下载 CLI 专用依赖。

**改动**：

- `tsdown.config.ts` 的 node 目标增加 `deps.alwaysBundle: ['citty']`：`citty`（零运行时依赖）内联进共享 CLI chunk，`dist/index.mjs` 不受影响。
- `package.json`：`citty` 从 `dependencies` 移到 `devDependencies`，运行时依赖面收敛为 `axios` / `zod`。
- `scripts/verify-package.mjs` 新增门禁：
  - tarball 的 `dependencies` 不含 `citty`；
  - `dist/*.mjs` 的外部 import 必须全部声明在 `dependencies`（未声明的 bare import 会在消费者机器上解析失败）；
  - `dist/index.mjs` 的静态 import 闭包不含 CLI chunk。

**验证**：

- `pnpm build`：`dist/cli*.mjs` 无 `citty` bare import；`dist/index.mjs` 闭包只有 `WeiboSDK-*.mjs`。
- `pnpm run verify:package`：新增三条断言全部通过，`node dist/cli-bin.mjs --version` 仍输出 `0.3.0`。
- `pnpm run typecheck` / `pnpm test --run` / `pnpm run lint`：见本轮提交前门禁。

**提交计划**：`build: inline cli-only citty dependency`（代码 + 门禁 + 文档同步）。
