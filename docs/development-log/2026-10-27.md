## ITweet 下游定位修正

`website/reference/tweet-contract.md` 首段把 `ITweet` 写成「下游 Weibo-archiver 的展示与 IndexedDB 存档结构」。这句是 2026-08-10 审查时的事实，现在消费端改由桌面应用承接、老格式与前端都要重做，前提不再成立。

- `ITweet` 改为 SDK 自己的存档契约，按契约版本演进；老 `Post` 格式只保留一次性导入。
- 作废 `p2-readiness.md` P2-2 裁定第 1、3 条（最小展示契约、`card` 不进契约），它们按老下游 UI 拍板。
- 保留契约版本机制与 raw sidecar 边界：版本保护的是已经写出的 JSON，不是下游内存结构。
- 新方向记录在 [research-itweet-v3-2026-10-27.md](../planning/research-itweet-v3-2026-10-27.md)：v3 为单一富契约，字段清单来自真实数据审计。

同步修正 `docs/README.md`、`backlog.md`、`website/reference/tweet-contract.md`。本次无代码变更。

## ITweet v3 与归档 v3（0.7.0）

按上一篇的定位落地契约升级。字段来自 714 条真实 fixture 的键频审计，不凭直觉：

- **收敛**：`readCount` / `playCount` / `editCount` → `stats.reads` / `stats.plays` / `stats.edits`；`isTop` / `isOriginal` → `flags.pinned` / `flags.original`。
- **新增**：`flags`（`ad` / `paid` / `edited` / `editable`）、`editedAt`、`tags`、`superTopic`、`contentNotices`、`stats.favorites`、`TweetMedia.focusPoint`、`TweetPageCard.summary`。
- **审计中不建模**：`cardid`、`common_struct`、`multi_attitude`、`annotations`、`number_display_strategy`（语义未确认或属于内部字段）。
- 归档格式升 `weibo-user-archive/v3`，新增 `schemas/weibo-user-archive/v3.json`；v2 schema 文件保留为历史。`mergeArchiveFiles` / `weibo-cli archive merge` 读取 v2 时把记录迁移到 v3，输出恒为 v3。
- 新增 `migrateTweetV2toV3` 纯函数，递归处理 `retweetedStatus` / `comments` / `replies` / `replyTo`；v1 → v2 迁移函数保留。
- 契约测试改为 `tests/unit/contract/itweet-v3.test.ts`，运行时键集基于 `mymblog_page1.json`；新增 tags / superTopic / contentNotices / editedAt / focusPoint 的真实 fixture 断言。
