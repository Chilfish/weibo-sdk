## 消费端应用调研与 POC 计划

**背景**：前身项目 `Chilfish/Weibo-archiver`（油猴脚本 + 网页查看器 + Go 本地服务器）已验证需求，但数据格式与前端都需要重做；同时要回答「桌面端用 MyGo 还是 Electron」。

**调研结论**：

- 纯网页不能承担抓取：浏览器禁止设置 `Cookie` 头、`weibo.com` 不开放 CORS、图片有 Referer 校验、IndexedDB 不适合大归档。
- MyGo 的两个能力正好接上 SDK：`mygo.Cookies` 能读 HttpOnly Cookie；`@mygo-plugins/fetch` 从 Go 发请求、不受 CORS 限制且可设 `Cookie` / `Referer` / `UA`，形状与 SDK 的 `fetchTransport({ fetch })` 一致。
- 因此采用「SDK 跑 WebView、Go 只做特权 I/O」：不把 SDK 移植到 Go，也不引入 Node sidecar。
- 两个明确限制：fetch 插件不暴露 `Set-Cookie`，应用内不能做访客模式；SDK 循环绑定页面生命周期，必须用 `UserArchiveStore` 落 SQLite 续跑。
- 老归档可以导入，但评论区楼中楼、关注、收藏会有信息损失，需要显式提示。
