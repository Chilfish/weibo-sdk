# 2026-11-01

## `UserArchiveStore` 分页：续跑不再构造整表数组（#22）

**问题**：消费端（Weibo Archiver 桌面宿主）用 SQLite 承载 `UserArchiveStore`，`userArchive.stream({ store })` 续跑时 SDK 调用 `loadRecords()` 判断哪些记录已完成，宿主只能把整库时间线记录拼成一个数组交给页面。100k 档实测 916 MB / 44.6 s，启动与续跑不可用。

**改动**：

- `UserArchiveStore` 新增**可选**的 `loadRecordsPage()`，入参 `{ slice?, cursor?, limit? }`，返回 `{ records, hasMore }`。顺序固定为 `createdAt` 倒序、同一时间 `mblogId` 倒序；游标 `(createdAt, mblogId)` 要求唯一。页大小由 SDK 钳制到 100–500（默认 200），store 不再二次钳制。
- 新增 `src/services/public/userArchive/records.ts`：
  - `iterateUserArchiveRecords()`：有分页就按游标翻页，没有就回退 `loadRecords()` 按页切分（旧行为）；空页、`hasMore: false`、游标不前进三种情况都停止，坏实现不会死循环。
  - `createUserArchiveRecordIndex()`：只保留去重后的「评论 / 楼中楼计数 + 需要重试的记录正文 + 是否完成」，不再持有整库正文。去重规则与 `dedupeUserArchiveRecords()` 一致。
- `UserArchiveService.stream()` 用索引替换两处 `loadRecords()`：开头的续跑判断、结尾的汇总统计；`commit()` 与重试循环改成 `index.add(entry)`。`run()` 仍需整表组装 `ArchiveFile`，保持原样。
- 内存 store 实现 `loadRecordsPage`：按 `(createdAt, mblogId)` 建一次有序快照，写入时失效；因为重试会重复写入同一个 `mblogId`，快照先按 `dedupeUserArchiveRecords()` 去重，保证游标键唯一。
- CLI 的 `FileUserArchiveStore` 不实现分页：它只服务 `run()`，本来就要整表组装；SDK 回退路径行为不变。

**验证**：`unit/services/UserArchiveRecords.test.ts`（钳制、游标推进、回退、死循环守卫、索引去重与统计、内存 store 分页一致性）、`component/public/UserArchiveService.test.ts` 新增两条：续跑时包一层「`loadRecords()` 直接抛错」的 store 仍能跑完并给出正确汇总；stale 记录从分页读出后走重试分支。

**兼容**：`loadRecords(slice)` 行为不变，旧 store 不需要同步升级；新增方法缺省即回退。新增的 `UserArchiveRecordCursor` / `UserArchiveRecordPageRequest` / `UserArchiveRecordPageResult` 登记为 Stable。

## 0.7.0 装机审计的可用性修复（#21）

**问题**：审计报告列了 P0–P3 共 14 条，核心是「调用方拿到干净的空列表，无法区分真的没有数据和被风控挡住」，其余是安装指引指向第三方同名包、CLI 静默忽略未知参数、4xx 被标成可重试、帮助表格按字符数而非显示宽度对齐。

**改动**：

- 空页语义：`TweetRepostsPageResult` 增 `emptyReason`（`gated` / `none` / `unknown`）与 `emptyTip`，上游 `empty_tip` 非空且空页时标 `gated` 并保留原文。`TweetCommentsPageResult` 增 `emptyReason`，只有 `total_number === 0` 才是 `none`，其余空页标 `unknown`——热度排序空页与风控拦截在响应结构上无法区分，不用文案猜语义。`tweets.context` 在抽样评论为 0 条而上游计数 > 0 时写入 `unknowns`。
- 错误分类：新增 `UpstreamRejectedError`（`UPSTREAM_REJECTED`，`retryable: false`），`mapHttpFailure` 把 4xx（429/432 与访客 403 登录门控之外）映射到它；`NetworkRequestError` 只保留 5xx 与无 HTTP 响应的传输失败。归档的 `retry` 策略读 `error.retryable`，不再对 400 白等三轮退避。
- CLI：`cli-bin` 先检查 Node 版本再动态加载依赖，低于 20.16 直接提示升级；`assertKnownFlags` 在 `runMain` 之前按命令参数表校验 flag（含别名、`--no-*`、值型参数的取值），未知时报 `CONFIG_INVALID` 并给最接近的候选；`renderCliUsage` 自渲染帮助，按显示宽度（CJK 记两列）对齐并把多行描述拆成续行；`getCookie` 与 archive 的三个参数错误改成抛结构化错误，CLI 错误统一 JSON。
- 分页与归一化：`likers` 的 `page` 改成本次请求页码、下一页放 `nextPage`（流内部改读 `nextPage`）；访客的 `getFollowings` / `getFans` 返回 `partial: true`；`TrendItem` 保留上游 `realpos` / `rank`，Markdown 榜单按 `realpos` 编号。
- 能力清单每条新增 `sdk` 字段，给出可直接运行的调用路径（`users.timeline` 实际挂在 `sdk.tweets` 上）。
- CLI `tweet detail --format markdown` 改为复用 `context` 投影，`--full` 追加评论抽样；JSON 视图仍是单次 `statuses/show`。
- 文档：`npx weibo-cli` 全部改为 `npx -p @chilfish/weibo-sdk weibo-cli`（npm 上的 `weibo-cli` 是另一个包），补充 Node 自检与 4xx 错误码说明。

**验证**：`api-surface.json` 登记 `UpstreamRejectedError` 并重新生成快照；新增 `unit/cli/validateArgs.test.ts`（别名、`--no-*`、`--` 终止符、值型参数、拼写建议、子命令前误写）、`unit/cli/usage.test.ts`（显示宽度、列对齐、无尾随空格）、`unit/cli/nodeVersion.test.ts`；`component/public/TweetService.test.ts` 补 gated/none/unknown 与 `comments_hot_empty` 真实 fixture；`GuestReads` 补 `partial`；`Collections` 补 `realpos` 编号。`pnpm typecheck` / `pnpm test`（1075 passed）/ `pnpm lint` / `pnpm check:api` / `pnpm check:docs` 全绿。

**兼容**：新增字段与错误码都是加法；`likers.page` 语义修正后旧调用方若把 `page` 当作下一页会少翻一页，改读 `nextPage`。
