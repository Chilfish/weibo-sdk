## 发布事故：npm publish 打包 `catalog:` 依赖 → 0.1.1 重发

**现象**：0.1.0 发布后，`npm i -g @chilfish/weibo-sdk@0.1.0` 报 `EUNSUPPORTEDPROTOCOL: Unsupported URL Type "catalog:"`。

**根因**：维护者手动执行的是 `npm publish`；npm 不解析 pnpm `catalog:` 协议，把 `"axios": "catalog:"` 等原样写进产物 `package.json`。同一源码用 `pnpm pack` 时依赖会被重写为 `^1.20.0` / `^0.2.2` / `^4.5.4`。

**处置**：

- `npm unpublish @chilfish/weibo-sdk@0.1.0 --force`（72 小时内、零依赖方），用 `pnpm publish` 重发 `0.1.1`。
- 核验：registry `dist-tags.latest = 0.1.1`；tarball `dependencies` 正常；临时目录安装后 `node dist/cli.mjs --version` → `0.1.1`。
- 新增 `scripts/verify-publish-tool.mjs`：`prepublishOnly` 检测 `npm_config_user_agent`，非 `pnpm` 直接失败（`npm run prepublishOnly` 已验证 exit 1，`pnpm run prepublishOnly` 通过）。
- 沉淀 [postmortem 010](../postmortem/010-npm-publish-catalog-protocol.md)，并同步 release checklist（禁止 `npm publish`、发布后解包核验依赖）。

**遗留**：

- registry 里还有 `0.0.0-stage`（02:25:40 发布的无依赖 / 无 bin 占位版本），当前 `latest` 已指向 `0.1.1`；npm 页面仍有 CDN 缓存，显示旧标签。

## Cookie 支持文件路径（SDK + CLI）

- 新增 `src/utils/cookieInput.ts`：`resolveCookieInput`（路径探测 + 读取 + 解析）+ `parseNetscapeCookies` / `parseCookieHeaderContent`（纯函数，可单测）。
- 解析规则：Netscape 7 列 TSV（支持 `#HttpOnly_`、跳过注释行与过期条目、同名后写覆盖），只保留 `weibo.com` / `weibo.cn` / `sina.com.cn` 域名；header 文件支持 `Cookie:` 前缀与多行；无有效条目 / 路径不存在 / 无微博 Cookie 抛 `InvalidConfigError`（`CONFIG_INVALID`，`context.path` 指路）。
- 浏览器安全：不静态 import `node:fs`，通过 `process.getBuiltinModule('node:fs')` 按需取用；浏览器环境退化为原样字符串（`dist/browser.mjs` 构建与导出面检查通过）。
- 接入点：`WeiboSDK` 构造时解析一次（避免每个 Service 重复读文件）；`AuthService` 兜底（直接构造也生效）；`FetcherService` 请求拦截器改用 `AuthService` 的解析结果；CLI `getCookie` 统一解析并在失败时打印友好错误 + exit 1。

- 真实文件复核（本机 Netscape 导出）：解析出 6 条微博 Cookie（含 `SUB` / `SUBP` / `XSRF-TOKEN`），header 长度 517；`sdk.checkSession()` 返回 `true`，`whoami --cookie <path>` 退出码 0。

## D8–D11：点赞者 / @我 / 消息 / 分组 + 归档接入（D1 / D2）

**抓包方式**：用 `.env` 中的 Cookie 走 Node `fetch`（与 SDK 相同的 `Cookie` / `X-XSRF-TOKEN` / `Referer` / UA），原始响应落到 scratchpad，脱敏后入库；分页行为逐页复核。

## 评论区参数修正（`buildComments`，2026-10-20）

**触发**：试玩首页 Feed 后跑 `tweet comments`，`total_number=51` 但流式只产出 8 条；同一微博用浏览器抓包首屏却有 20 条。

**抓包**：OpenCLI browser bridge 复用已登录 Chrome。真实请求：

`GET /*/ajax/statuses/buildComments?is_reload=1&id=<数字 mid>&is_show_bulletin=2&is_mix=0&count=10&uid=<uid>&fetch_level=0&locale=zh-CN`

**根因**：SDK 固定传 `type=feed`。7 组参数对照确认：带 `type=feed` 首屏只回 3 条（`ok` / `total_number` / `max_id` 仍正常，静默降级），去掉后回 20 条；`id` 形态（mblogId / 数字 mid）、`uid`、`locale`、`count` 都不是原因。

**其他实测结论**：

- 翻页必须用响应顶层 `max_id`；拿「最后一条评论 id」当游标在顶层评论会返回 0 条。
- `count` 被上游忽略（10 / 20 均返回约 20 条）。
- `flow=1`（按时间）要求数字 mid，字母 mblogid 返回 HTTP 400。
- 顶层 `total_number` 含楼中楼 / 不可见评论（实测 115 vs 顶层 51），不能作为结束条件。
- hot 排序可能先返回空页（`data: []`、`max_id` 仍非 0）；后续再请求该 `max_id` 才变 0。
- `trendsText` 为「博主已开启防火墙，部分内容暂不展示」时，`data` 会少于 `total_number` 且 `max_id=0`（上游限制）。
- 楼中楼 `id=<一级评论 id>&is_reply=1&fetch_level=1` 正常；`rootid` 可选；大线程同样用响应 `max_id` 翻页。

**改动**：

- `buildCommentsSpec` 移除 `type` 参数（`.strict()` 下再传会直接报错）；响应 schema 增加 `trendsText` / `tip_msg`。
- `TweetService.comments()` 不再发送 `type=feed`；`flow=1` 且入参非数字时自动用 `statuses/show` 解析数字 mid。
- `streamCommentPages` 移除 `processed >= total_number` 停止条件，保留空页 / `max_id=0` / 游标不前进。

## 转发链配图丢失（`repostChain`，2026-10-20）

## 流式范围控制（`maxItems` / `since` / `until`，2026-10-20）

**触发**：试玩 `media images` 时发现自动翻页只能靠 `maxPages` 或手动游标，无法按「条数 / 日期」收口；增量只能逐页自行判断。

**方案**（`src/utils/streamRange.ts`）：

- 所有 `stream*` 新增 `maxItems`：按跨页去重后的产出计数，达到后停止翻页（`paginate` 同步支持，且不再请求下一页）。

- 起始游标 / 页码保持原语义（`page` / `maxId` / `sinceId` / `cursor`），继续用于断点续传与增量；`since` 与 `sinceId` 明确区分。

**CLI**：`--max-items` 全量接入 `*-stream`；`--since` / `--until` 接入时间序命令；新增 `weibo-cli user timeline-stream <uid>`（此前 SDK 有 `streamByUserId` 但 CLI 未暴露）。

- 移动端 `visitor.passport.weibo.cn` 的 `genvisitor → incarnate` token（domain `.weibo.cn`）在 PC 与 m 站都有效，作为唯一访客身份；`genvisitor2` 的 PC token 仅对 `weibo.com` 有效。

- **匿名翻页边界**：m 站 container 列表第 2 页 / `since_id` 一律 302 登录页；PC 评论 / 转发 / 媒体墙 / 视频瀑布可翻页。

**产出**：[research-guest-mode-2026-10-20.md](../planning/research-guest-mode-2026-10-20.md)（完整端点矩阵、分页矩阵、SDK 接入方案、P0/P1/P2 行动项）；[backlog.md](../planning/backlog.md) 新增 G1–G7 并撤销「无 Cookie 访客模式不再推进」的旧裁定；[docs/README.md](../README.md) 登记索引。

## 设计 + 实施：Agent 视角的微博上下文（TweetContext，2026-10-20）

**触发**：评估「如何让一个 AI 理解给定的微博」，尤其是图文微博与多层转发。

**方式**：用真实 Cookie 拉两条真实微博做投影原型：图文原创 `RnxWieuYE`（@差评君，1 张测试车谍照）与多层转发 `RnANTz33M`（@芋头_Sa74，4 层 `//@`，9 张图属于原微博）。

**关键结论**：

- `ITweet` 是存档记录，不是理解输入；新增独立的 `ITweetContext`（`weibo.tweet-context/v1`），不改 `ITweet` v1。
