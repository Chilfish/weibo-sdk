## Cookie 来源收口（只读 `.env`）

**现象**：`.env` 已更新为新 Cookie，但 `whoami` 仍报 `Weibo session expired`。

**根因**：`process.loadEnvFile()` **不覆盖已存在的环境变量**；本机 `WEIBO_COOKIE` 环境变量为 514 字符旧值（`profile/detail` 返回 `ok:-100`），`.env` 为 517 字符新值（`ok:1`）。CLI 一直读到旧值。

**决策（维护者）**：Cookie **只从指定 `.env` 读取**（默认 `<pwd>/.env`），不再回退到环境变量；`--cookie` 作为显式覆盖。

**复盘**：已沉淀 [postmortem 009](../postmortem/009-cookie-env-shadowing.md)（同一问题 2026-08-09 曾出现过一次）。

**落地**：

- 新增 `src/utils/envFile.ts`：用 `node:util.parseEnv` 解析文件，不写 `process.env`；缺失/非法文件返回空。
- `src/cli/shared.ts`：`getCookie()` 只读 `--env-file`（默认 `<pwd>/.env`）；`cookieArg` 增加 `--env-file`。
- `src/cli.ts`：移除顶层 `process.loadEnvFile()`；`whoami` 错误信息给出实际 `.env` 路径。
- `capture/`：同样只读 `.env`，`CaptureOptions.envFile` + CLI `--env-file`。
- E2E：新增 `tests/e2e/setup-env.ts`，测试前用 `.env` **覆盖** `process.env.WEIBO_COOKIE`；`vitest.e2e.config.ts` 改为该 setup。

**API（定稿）**：

- **请求级**：`config.hooks.onRaw(raw, meta)` —— 在 `okPolicy` / Zod 校验**之前**触发，成功、`ok !== 1`、schema 失败三种情况都能拿到 raw；meta 含 `endpoint/resourceType/request/args/trace_id/timestamp`。`onFetched` 保留并标记 `@deprecated`。

- **失败语义**：`onRaw` 抛错会使该请求 / 该条归档失败，不静默丢失 raw。

**落地文件**：`src/types/hooks.ts`、`src/services/internal/FetcherService.ts`、`src/services/public/ArchiveService.ts`、`src/services/public/TweetService.ts`、`src/types/index.ts`、`src/cli/commands/tweet.ts`（`tweet enrich`）、`src/cli.ts`。

## P1-1/P1-2：归档 checkpoint 瘦身 + 转发内联

**问题**（review R1/R2）：`visitedMblogIds` 每个 item 都随 checkpoint 序列化一次（O(N²)）且无消费方；reposts 阶段用 `collectTimelineMblogIds` 把 timeline 整个重放一遍。

**改动**：

- `ArchiveCheckpoint` 删除 `visitedMblogIds`，改为恒定大小：`{ uid, phase, page?, lastTimelineMblogId?, favoritesPage?, lastMblogId? }`。
- `page` 语义改为「timeline 当前页」（恢复时重跑该页，避免原先 `page + 1` 跳过页内剩余项）；`lastTimelineMblogId` 记录已完整处理（含转发）的最后一条，恢复时跳过。
- 分页幂等保护：单页内按 `mblogid` 去重；若整页 id 都是上一页的子集（上游忽略 page 重复返回），直接 break。
- reposts 改为 timeline 阶段内联：每条 timeline item 之后立即翻其转发页并 yield，删除 `collectTimelineMblogIds`；中断只会重跑当前 item 的 timeline + reposts（重复但不会漏）。
- 旧 checkpoint 兼容：`phase:'reposts'` 归一化为 timeline 第 1 页，并以 `lastMblogId` 作为 `lastTimelineMblogId` 跳过已完成项。
- CLI `archive` 的 done 事件改为本地计数，不再读取 `visitedMblogIds.length`。

**测试**：`ArchiveService.test.ts` 更新 checkpoint 断言与调用次数，新增「不再重放 timeline」「整页重复即停止」「恢复时跳过 lastTimelineMblogId」覆盖。

## P1-5：searchProfile 日期切片

**上游实测（OpenCLI Browser Bridge 绑定已登录 Chrome，未重启浏览器）**：

- 真实网页端请求：`GET /ajax/statuses/searchProfile?uid=...&page=1&q=...&starttime=<unix秒>&endtime=<unix秒>&hasori=1...`。
- `starttime/endtime` 是 **unix 秒**；此前 SDK 传日期字符串会被上游静默忽略（返回未过滤结果）。
- 单页约 50 条；`data.total` 在小范围可信，但大范围会失真（如 2024 全年 total=1179，实际子区间 Jan-Mar 869 + Mar-Jul 1024 + Jul-Dec 1161）。
- page 超过实际页数后会“重置”返回较新的区间（如 2025-01 第 15 页回到 Jan 8），因此必须在窗口内 `total` 超过安全阈值时先缩小窗口，并用日期单调性兜底停止。

**实现**：

- `searchByDate` 的 `starttime/endtime` 类型改为 `number | string`（字符串仅兼容透传），文档标注 unix 秒。
- `ArchiveService`：mymblog 翻到底后，若 `data.total` 表明仍有剩余（或 total 不可用），从最旧一条微博之前继续日期切片；`timelineSource:'search'` 可直接跳过 mymblog。
- 自适应窗口：默认 30 天，单片 `total > maxSliceItems`（默认 800）时对半缩小重试；空切片放大窗口（最大 5 年）加速跨过空档。
- 切片内继续用 page 翻页；按 `total`、空页、重复页、日期不再变旧停止，避免上游重置导致重复/漏页。
- checkpoint 新增 `sliceEnd` / `slicePage` / `sliceWindow`；`sliceEnd` 存在即恢复时跳过 mymblog，页内用 `lastTimelineMblogId` 跳过已处理项。
- CLI `archive` 新增 `--no-date-slices` / `--source mymblog|search` / `--since <unix秒>`。

**测试**：`ArchiveService.test.ts` 新增 7 条（回退切片、完整时跳过、密集窗口对半、切片续跑、上游重置停止、`timelineSource:'search'`、缺少依赖报错）；`SearchProfile.test.ts` 新增数值时间戳透传。真实冒烟：`timelineSource:'search'` 与 mymblog→切片回退均按预期产出，切片边界无重复。

### 发布前真实冒烟：发现并修复两个阻塞项

**1. CLI 负向开关失效（真实 bug）**

- 现象：`archive --no-reposts --no-favorites --no-date-slices` 仍会拉取转发/收藏。
- 根因：citty 对 `--no-X` 的处理是把 `args.X` 设为 `false`，不会产出 `args['no-X'] = true`；原实现读的是 `args['no-reposts']`，永远 `undefined`，于是 `!undefined === true`。
- 修复：参数改为正向布尔（`reposts` / `favorites` / `date-slices`，默认 `true`），统一走 `resolveArchiveIncludeFlags()` 映射；新增 `tests/unit/cli/archiveFlags.test.ts`（3 例）。
- 顺带修复：CLI `archive` 原先只在异常时写 checkpoint，Ctrl+C 中断无法续传；改为每产出一项即落盘（不再是发布阻塞点）。
- 真实验证：`--no-*` 全开后 20 条 item、0 条 repost；checkpoint 落盘 `{ phase: timeline, page: 1 }`；带 checkpoint 重跑得到 20 条新项、与首轮 0 重叠、checkpoint 前进到 page 2。
