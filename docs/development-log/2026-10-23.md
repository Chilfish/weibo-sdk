## 公开输出归一化（camelCase 契约）

**背景**：下游交接前审计公开面，发现领域模型已经 camelCase，但一批公开方法仍原样返回上游响应
（`screen_name` / `followers_count` / `next_cursor` / `data.longTextContent` 等），包根还导出了
42 个 snake_case 的 `*Response` 类型。下游拿到两套形状，DX 和契约稳定性都不成立。

**决策**：

1. 公开方法一律返回归一化 camelCase 模型；raw 只保留在显式 `fetchRaw*`。
2. 包根不再导出 raw 响应类型。
3. telemetry / hooks / logger 的 Wide Events 字段保持现状（可观测性契约，不是微博数据）。
4. 不保留兼容别名，直接删除被取代的 `getFavorites` / `FollowingUser`。

**实施计划**：[todo-output-normalization.md](../archive/todo-output-normalization.md)（已完成并归档）。

**涉及**：`UserBrief` / `ISelfProfile` / `TrendItem` / `FavoriteTag` 新模型；followings、tweets、
favorites、trends、users、search 六个 service；`WeiboSessionContext.details → profile`；CLI 与公开文档。

**结果**：六笔提交完成；离线测试 971 passed / 28 skipped，真实 E2E 28 passed（含 guest）。

## API 分层：Experimental → Evolving + 方法层级门禁

**背景**：101 个「Experimental」导出里没有一个是实验性能力——45 个 `*Options`、19 个 `*Progress*`、
19 个运行时标签，其余是 helper / 凭据 / 插件形状。真正随上游漂移的 `fetchRaw*` 是 service 方法，
而 tiers 只覆盖包根导出，方法层级一直靠散文维护。

**决策**：

1. `Experimental` 改名为 `Evolving`，表示「可调用，但形状随 minor 演进」；`Experimental` 只留给
   可能被撤回的能力（当前 0 条）。
2. 16 个归一化 / id 解析 / 上下文渲染 / schema diff helper 移出包根（Internal）。
3. 导出索引改为 tier × shape 两维：Stable 平铺，Evolving 按 options / progress / runtime /
   extension / utility 分组。
4. `check:api` 新增 `methodTiers.evolving`：19 个公开 `fetchRaw*` 必须显式登记，新增 raw 方法
   未登记即失败；`@internal` 的 `fetchRawPage` 不在此列。
5. 顺手修复 `--write` 写错生成页路径的既存 bug（`website/types/index.md` →
   `website/api/types/index.md`，站点导航一直指向后者）。

**结果**：267 exports（166 Stable / 101 Experimental）→ 251 exports（166 Stable / 85 Evolving）；
新增 `tests/unit/scripts/check-api-surface.test.ts` 6 条用例。
