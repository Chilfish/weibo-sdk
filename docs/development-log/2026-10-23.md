## 公开输出归一化（camelCase 契约）

**背景**：下游交接前审计公开面，发现领域模型已经 camelCase，但一批公开方法仍原样返回上游响应
（`screen_name` / `followers_count` / `next_cursor` / `data.longTextContent` 等），包根还导出了
42 个 snake_case 的 `*Response` 类型。下游拿到两套形状，DX 和契约稳定性都不成立。

**决策**：

1. 公开方法一律返回归一化 camelCase 模型；raw 只保留在显式 `fetchRaw*`。
2. 包根不再导出 raw 响应类型。
3. telemetry / hooks / logger 的 Wide Events 字段保持现状（可观测性契约，不是微博数据）。
4. 不保留兼容别名，直接删除被取代的 `getFavorites` / `FollowingUser`。

**实施计划**：[todo-output-normalization.md](../archive/todo-output-normalization.md)（已完成并归档）。

**涉及**：`UserBrief` / `ISelfProfile` / `TrendItem` / `FavoriteTag` 新模型；followings、tweets、
favorites、trends、users、search 六个 service；`WeiboSessionContext.details → profile`；CLI 与公开文档。

**结果**：六笔提交完成；离线测试 971 passed / 28 skipped，真实 E2E 28 passed（含 guest）。
