## proot 下的 bun 安装与 Skill 入口（#23）

**问题**：Termux / proot 使用 `link2symlink`。bun 1.4 在该环境把安装缓存写成 `.l2s.*` 备份文件。安装退出码是 0，加载包时报 `ENOENT` 或 `ERR_UNKNOWN_FILE_EXTENSION`。README 只给了 npm 的 `npx -p` 写法。Skill 默认要求 clone 仓库并安装整套 devDependencies，读取数据也要先建源码环境。`scripts/weibo.sh` 找不到仓库时退出码 64，没有全局 bin 退路。

**改动**：

- `README.md`、`website/guide/installation.md`、`website/cli/index.md`：补充 `bun add`、`bunx -p @chilfish/weibo-sdk weibo-cli`、`bun add -g` 写法。注明包名与 bin 名不同。新增 Termux / proot 小节，给出清缓存后使用 `--backend=copyfile` 的步骤。
- `.agents/skills/weibo-sdk/SKILL.md` 升到 2.1.0。默认路线改为消费已安装的 `weibo-cli`。源码直跑改为改代码、修端点时的进阶路径。新增「运行环境（Linux / 容器 / proot）」一节。故障排除补充 `.l2s.*` 缓存残留。
- `.agents/skills/weibo-sdk/scripts/weibo.sh`：入口按仓库源码、bun 全局 dist、PATH 全局 bin、`bun x -p` 的顺序查找。仓库或依赖缺失时自动回退。`--doctor` 增加模式、node 版本、全局 CLI 版本与 bun 缓存残留检查。`--where` 输出实际入口。
- `AGENTS.md`、`website/agents.md`、Skill 的 `references/cli.md` 与 `references/sdk.md`：同步包名、bin 名和默认路线。

**验证**：`bash -n` 通过。仓库内 `--doctor` 输出 `mode: source` 与 deps ok。把脚本复制到仓库外，依次验证 `bunx`、`bin`、`dist` 三种回退。伪 `.l2s.*` 缓存被 `--doctor` 检出，退出码 1，并输出修复命令。`pnpm check:docs` 通过，48 个站点页面与 README 无内部引用或字段漂移。`pnpm docs:build` 通过。
