# Taste
- Favors a lean toolchain: when a tool adds friction (e.g. `size-limit` / `@size-limit/preset-small-lib` bundle-size gates), prefers removing the whole thing rather than fighting its configuration. Confidence: 0.65
- Before locking in next steps, wants docs and code first brought in sync with the current state (no documentation drift) — "先把相关的文档和代码更新到最新的状态，然后再敲定后续的步骤"; when a planning doc's checkboxes lag behind finished code (e.g. task list / roadmap still unticked), expects them back-filled to match reality ("确实得同步文档状态"). Confidence: 0.7
- Treats the repo's planning docs as the source of truth for sequencing: next steps should be taken from what the roadmap / action plan / release checklist says ("按照文档的说明来继续完成后续的步骤") instead of inventing new priorities. Confidence: 0.65
- Expects prior-art research before building: asks the agent to search GitHub for still-active, similar projects to reference, and repeatedly frames progress reviews as a competitive gap analysis — "相较于调研到的在活跃着的类似的微博逆向项目来说，我们还少了啥" — i.e. states what's missing by comparison with maintained competitors, not just against the internal roadmap. Confidence: 0.7
- When referencing existing projects, prefers recently updated/maintained repos over older ones, since upstream APIs change a lot. Confidence: 0.65
- Judges work by whether the exported interface is genuinely usable by downstream consumers, not just internally passing gates. Confidence: 0.55
- Writes in casual, concise Chinese; comfortable rejecting a tool with a short one-liner and expecting the agent to work out the full cleanup scope. Confidence: 0.5
- Wants secrets/config (e.g. `WEIBO_COOKIE`) read from one explicitly specified file only (default: `.env` in the current working directory) — no fallback chain to environment variables, since stale env vars silently shadow the real value. Confidence: 0.75
- Prefers deterministic single-source-of-truth config resolution over convenience fallbacks; fixing config plumbing should remove the implicit source rather than document it. Confidence: 0.6
- Quick manual verification should run the TypeScript entrypoint directly with `bun` (e.g. `bun ./src/cli.ts tweet detail <id>`) instead of building first and invoking the compiled output — fast feedback loop preferred. Confidence: 0.7
- While still in the planning/definition phase, wants the agent to hold off on code changes and first finish documentation and research (调研) — scope should stay on docs + investigation until the plan is settled. Confidence: 0.65
- Keeps the core data contract thin: prefers not embedding upstream raw payloads (raw JSON) into the archive/export envelope — downstream consumers should persist raw themselves, while the SDK exposes it through hooks/callbacks ("类似 hooks 或者别的什么方法") plus a separate `enrich` method. Confidence: 0.7
- Once gates pass, wants work landed on `main` right away (merge the feature branch in, keep the split commits, delete the temp branch) — treats a green local branch as ready to merge rather than keeping it pending for review. Confidence: 0.5
- Sequences work smallest-and-safeest first: start with the small item that directly serves downstream consumers and does not touch the frozen data contract, then move on to the large-scale refactors ("它小、直接服务下游，也不会改 ITweet 契约；之后再进入…规模化改造"). Confidence: 0.55
- Wants work committed at the end, "按规范" — i.e. split into focused, conventionally-prefixed commits following the repo's documented git workflow (chore/fix/test/docs per theme) rather than one bulk commit. Confidence: 0.65
- Expects the agent to "随手 commit" — commit incrementally at each natural boundary as work progresses (docs commit, then code commit, then each follow-on task), without being reminded and without waiting until everything is done. Confidence: 0.85
- Treats passing self-checks as the go-ahead: once typecheck/tests/build are green, wants the agent to move on to the next planned step on its own rather than pausing for approval ("你自测没问题后可以下一步"). Confidence: 0.7
- Keeps repo conventions vendor-neutral: dislikes agent-/tool-specific conventions in docs (e.g. a required `claude/*` branch prefix) and wants them removed in favor of generic feature-branch naming; historical logs recording old branch names are fine to leave as-is. Confidence: 0.6
- Prefers empirical verification against real live traffic over doc-based inference: wants the agent to drive their already-logged-in Chrome (e.g. via agent-browser / OpenCLI-style CDP auto-connect) and intercept the actual requests to learn/validate an upstream API's real behavior — offers it as a standing option ("你还可以使用 … 这样的方式来调试我已经登录好的 Chrome，拦截微博的请求等来分析或者验证"). Confidence: 0.7
- Comfortable letting the agent operate their real authenticated local environment (personal Chrome profile / active login session) for probing, and points at a third-party tool's docs as a suggestion while leaving the concrete mechanics to the agent; but prefers attaching a debugger (CDP) to the Chrome they are already using over restarting it, installing an extension, or copying cookies into an isolated profile. Confidence: 0.7
- When they name a specific tool or approach, expects the agent to actually pursue it or explicitly say why it deviated — pushes back with a short "为啥不是用 X 的方案？" when the agent substitutes its own choice instead. Confidence: 0.65
- Expects the agent to exploit parallelism: spawn sub-agents for tasks that don't conflict with each other instead of working serially ("你可以开子agents来并行完成那些不互斥的任务"), provided the tasks are non-mutually-exclusive. Confidence: 0.7
- Treats "验证 + commit" as the closing milestone of a work batch: checks in with a terse "现在啥状态？能验证commit了吧" / "我感觉差不多了，可以先commit所有的更改" expecting a compact status summary (what's done, what's still running/remaining) followed by full-gate verification and the actual commits, not another round of feature work. Confidence: 0.65
- When they call for a commit, they mean land everything currently in the working tree ("commit 所有的更改") — don't hold the commit back waiting for the last in-flight nice-to-have (e.g. a TSDoc sub-agent still running); wrap it up and commit what is green. Confidence: 0.5
- Separates "commit" from "release": comfortable letting the agent commit locally, but wants irreversible/publishing actions (npm publish, tag push, GitHub Release) held until an explicit decision — given the choice, picks "只提交，不发布". Confidence: 0.6
- Will self-install the prerequisites the agent asks for (Chrome extension, npm package) and then report "已经装好了" expecting the agent to immediately continue down that supported path — prefers enabling the official integration over improvised workarounds (e.g. copying cookies into a throwaway profile). Confidence: 0.55
- Wants every outstanding task written into a repo planning doc ("把所有的待办记录到文档里") so the action list — not chat history — carries the backlog; considers the plan durably recorded only once it lives in a doc. Confidence: 0.8
- Prefers publishing under a scoped npm name (`@chilfish/weibo-sdk`) while keeping the CLI binary short and stable (`weibo-cli`) — binary name intentionally decoupled from package name. Confidence: 0.7
- Judges the product by user-data breadth, not just timeline/favorites: expects continued enrichment of what a real profile exposes (likes, favorites, posted comment history) because "一个用户的微博数据还是比较丰富的". Confidence: 0.7
- Treats endpoint add/modify developer experience as a first-class requirement to design for ("后续我们增加或修改相关接口时的开发体验之类的也得考虑进来"), not an afterthought. Confidence: 0.7
- Scopes new capabilities to what the web version actually exposes — if the website has an ajax endpoint for it, it's in scope ("实际上都有在网页版有对应的接口能获取"). Confidence: 0.6
